Докер контейнер - запущенный контейнер по шаблону докер образа (как объект для класса)

Шаги:
0) Сформировать мануальный алгоритм запуска тестов и репорта
1) Создать докер образ на основе тестов (шаблон)
2) Запускать тесты на основе докер образа внутри докер контейнера
3) Достать репорт по результатам тестов из докер контейнера
4) Сложить результат в специальную папку результата

Зачем? Кейс использования

QA1 -> разрабатывают тесты (вся техника: java, mvn и тд)
QA2 -> разрабатывают тесты (вся техника: java, mvn и тд)
DEV1 -> просто запустить тест (без понимания техники)
DEV2 -> просто запустить тест (без понимания техники)

QA1 -> упаковывают новую версию тестов в "коробку" (докер)
QA2 -> упаковывают новую версию тестов в "коробку" (докер)

DEV1 -> берут и запускают обновленные тесты из "коробки" (используя докер)
DEV2 -> берут и запускают обновленные тесты из "коробки" (используя докер)
